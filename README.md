# リードタイム一括更新 Webサービス(自社専用)

ブラウザで日数を入力し、出品者出荷の全SKUのリードタイムをまとめて変更します。
価格には触れません。在庫数は、更新の直前に読み取った現在の値をそのまま送り直します。

## ファイル

| ファイル | 内容 |
|---|---|
| `app.py` | サービス本体(Python標準ライブラリのみ) |
| `Dockerfile` | クラウドに載せるための定義 |
| `render.yaml` | Render 用の設定(Render を使う場合のみ) |

## 設定する環境変数

認証情報はファイルに書かず、クラウドの「環境変数(Environment / Secrets)」に登録します。

| 名前 | 内容 |
|---|---|
| `APP_PASSWORD` | 画面にログインするパスワード(8文字以上。長く推測されにくいもの) |
| `SP_CLIENT_ID` | LWAクライアントID |
| `SP_CLIENT_SECRET` | LWAクライアントシークレット |
| `SP_REFRESH_TOKEN` | リフレッシュトークン |
| `SP_SELLER_ID` | 出品者ID(出品者トークン) |
| `DEMO_MODE` | `1` にするとAmazonに接続せずダミーデータで動く(動作確認用) |

## まず手元で画面を確認する(任意)

```
DEMO_MODE=1 APP_PASSWORD=好きなパスワード python app.py
```

ブラウザで http://localhost:8080 を開きます。Amazonには接続しません。
(Windows のコマンドプロンプトでは `set DEMO_MODE=1` のように1行ずつ設定してから `python app.py`)

## クラウドへの設置(Render の例)

1. この3ファイルを GitHub の**非公開(Private)**リポジトリに置く
2. Render で新しい Web Service(または Blueprint)を作成し、そのリポジトリを選ぶ
3. 上の環境変数5つを登録する
4. デプロイ完了後に表示される `https://〜.onrender.com` を開いてログイン

Dockerfile があるので、Google Cloud Run、Fly.io、Railway などでも同じ要領で動きます。

### 設置先を選ぶときの条件

- **インスタンスは1台だけ**にしてください。進捗をメモリ上で管理しているため、
  複数台に分散すると進捗が正しく表示されません。
- 更新中はバックグラウンドで処理が続きます。
  - Render の無料プランは、アクセスがないと一定時間で停止します。
    **更新が終わるまで画面を開いたままに**してください。
  - Cloud Run では「CPUを常に割り当てる」設定にし、最大インスタンス数を1にしてください。

## 使い方

初回は必ず 1 → 2 の順で確認してください。

1. 「1商品だけで試す」にSKUを入れて実行し、数分後にセラーセントラルで
   **在庫数が変わらず、リードタイムだけ変わった**ことを確認する
2. SKU欄を空にして日数を入力 →「対象の商品を確認する」→ 件数を確認 →「◯件を◯日に更新する」

「確認のみ行う」にチェックすると、各SKUの現在の在庫数とリードタイムを読み取るだけで、設定は変わりません。
完了後は SKUごとの結果をCSVでダウンロードできます。

## 履歴

画面の下に、過去の実行(日時・内容・成功と失敗の件数)が一覧で残ります。
各行の「CSV」から、SKUごとの**変更前の日数**と設定した日数を確認できます。
「確認のみ」の実行も残るので、変更前に全商品を確認しておくと、元の設定の記録になります。
最新200件まで保存します。

履歴を残すには、RenderでDiskの追加が必要です(有料プランのみ)。

1. サービスのプランを Starter 以上にする
2. サービスの「Disks」→「Add Disk」→ Mount Path に `/data`、サイズ 1 GB
3. 保存すると再デプロイされる

Diskがないと、履歴はサービスの再起動や再デプロイで消えます(画面にその旨が表示されます)。

## 知っておくこと

- **在庫数の扱い:** Amazonはリードタイムだけの更新を受け付けないため、更新の直前に
  SKUごとの現在の在庫数を読み取り、その値と一緒に送っています。読み取りから更新までの
  ごくわずかな間(1秒未満)に注文が入ると、その1件分の在庫が元に戻ることがあります。
  注文の少ない時間帯に実行すると、影響を減らせます。

- 処理速度は1秒あたり約4件です(1,000 SKUで約5分)。
- 反映には数分〜15分ほどかかります。
- 元の日数に戻す機能はありません。戻すときは通常の日数でもう一度実行します。
  SKUごとに違う日数を設定していた場合、その差は失われます。
- サービスを再起動すると、ログイン状態と直前の結果は消えます(Amazon側の設定には影響しません)。
